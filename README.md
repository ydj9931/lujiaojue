# 鹿角蕨 Lujiaojue

> **从你的工作里，长出你的工作台。**

鹿角蕨运行在 WorkBuddy、Codex、Claude Code 等能够操作本地文件的超级 Agent 中。

它不会再给你增加一套需要维护的管理系统，而是从你已经存在的文件和项目开始：

```text
减少混乱 → 让重复工作更省力 → 推动成果 → 让价值继续生长
```

一句话：

> **先减熵，再提效，做成成果，形成复利。**

鹿角蕨的做事方式是：

> **灵魂是顾问，落实是助理。**

它不只告诉你“哪里有问题”，还应该在你确认后，利用宿主 Agent 把正确的判断落实到真实文件和当前事实中。

---

## 1. 安装

你需要先有一个能够读取和操作本地文件的超级 Agent。

### Claude Code

本仓库可以直接作为 Plugin 使用。

本地测试：

```bash
claude --plugin-dir ./lujiaojue
```

仓库发布后也可以通过 Plugin Marketplace 安装。

### Codex

把仓库地址直接交给 Codex：

```text
请从 https://github.com/ydj9931/lujiaojue 安装鹿角蕨，
并将 skills/lujiaojue、skills/fuli、skills/xiaowang
安装为全局可复用 Skills。
优先使用你原生的 Skill / Plugin 安装机制。
安装后验证三个 Skill 都可以被发现。
```

### WorkBuddy

把仓库地址交给 WorkBuddy，通过 Skills 入口安装：

```text
请从 https://github.com/ydj9931/lujiaojue 安装鹿角蕨，
并同时安装鹿角蕨、富丽和小王三个 Skills。
推荐全局安装。
```

> **安装只需要做一次。**

---

## 2. 第一次使用

安装后，**用你的 Agent 打开一个你平时真正工作的文件夹**。

不知道选哪个？

> 先选最近最常工作的那个，不需要一次扫描整个电脑。

然后说：

```text
鹿角蕨初始化
```

鹿角蕨会先告诉你：

> 我会先看看这个文件夹里你正在做哪些工作，不会移动或修改你的文件。

然后自动：

```text
看看当前文件夹
→ 找出主要工作
→ 发现明显的混乱和重复
→ 识别可能正在形成的复用模式
→ 生成第一版工作台
```

第一次原则：

> **先理解，不折腾。**

鹿角蕨不会因为目录“不标准”就批量移动、重命名或重构你的文件。

---

## 3. 工作台看什么

说：

```text
鹿角蕨工作台
```

鹿角蕨会刷新当前文件夹，并重点展示四件事。

### 减少混乱

例如：

- 同一文档出现多个“最终版 / 最新版”；
- 重复副本；
- 多份可能代表当前事实的文件；
- 长时间没有更新、但仍混在活跃目录中的内容。

目标不是“把目录整理漂亮”，而是：

> **减少你理解当前工作所需要付出的成本。**

### 正在变得更省力

鹿角蕨会寻找重复出现的结构和做法，例如：

```text
连续多个项目都出现相似方案结构
→ 可能形成模板

同类工作反复使用相同步骤
→ 可能形成 Workflow / Skill
```

这些只会先标为**候选**，不会自动给你制造新的流程。

### 正在推进的工作

鹿角蕨会把最近真正活跃的工作放到前面。

当问题涉及目标、成果、责任、决策、偏航、验收时，会按需调用 **小王**。

例如：

```text
这个项目现在最关键的问题是什么？
这个项目是不是偏航了？
小王扫描
小王整理
```

### 正在长出来的东西

鹿角蕨会寻找那些可能跨越一次任务继续产生价值的东西：

- 方法；
- 案例；
- 模板；
- 课程；
- 手册；
- Workflow；
- Skill；
- 研究与作品；
- 可长期维护的资源。

需要进一步判断时，会按需调用 **富丽**。

例如：

```text
这次工作有什么值得留下来？
这个方法值得长期沉淀吗？
富丽扫描
```

## 4. 平时怎么用

初始化以后，不需要天天学习新命令。

继续像平时一样使用你的 Agent：

```text
帮我看看现在最重要的三件事。
```

```text
这些文件里哪一份才像当前版本？
```

```text
这个工作是不是已经重复到值得做成模板了？
```

```text
这个项目真正要交付什么？
```

```text
最近这些工作里，有什么已经形成长期价值？
```

鹿角蕨会尽量让普通任务继续由宿主 Agent 完成，只有需要专业判断时才加载小王或富丽。

Advisor 完成当前任务后自动退出。

## 5. 怎么用好

### 不要为了鹿角蕨重建文件系统

直接从真实工作开始。

你的文件本来就有些乱也没关系。

### 先减熵，再增加新东西

当系统发现问题时，优先问：

> 能不能通过删除重复、确认当前版本、复用已有内容解决？

而不是马上新建：

- 文件；
- 模板；
- 表格；
- 流程；
- 项目；
- Skill。

### 看到错误就直接纠正

例如：

```text
这个不是项目，是长期维护的讲师池。
```

```text
这两个文件夹其实属于同一项工作。
```

```text
这个文件虽然很久没更新，但仍然是长期有效资料。
```

鹿角蕨应该随着真实使用修正理解。

### 告诉鹿角蕨你的长期偏好

例如：

```text
能不新增文件就不要新增。
```

```text
默认只告诉我最重要的三件事。
```

```text
我喜欢先看结论，再看依据。
```

```text
不要为了目录整齐移动历史文件。
```

原则是：

> **先使用，再适配。**

## 6. 参与贡献

最有价值的贡献来自真实使用。

欢迎提交：

- 把正常文件误判为混乱的案例；
- 漏掉明显重复版本的案例；
- 没有发现真正重复工作模式的案例；
- Advisor 误触发或任务结束后没有退出；
- 让用户增加了额外管理负担的设计；
- 能明显让工作更清楚、更省力、更接近成果的改进。

如果要新增 Advisor，请先证明它解决的是一个长期、反复出现、普通 Agent 难以稳定处理的问题。

开发说明见 [`CONTRIBUTING.md`](CONTRIBUTING.md)。
