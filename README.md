# 鹿角蕨 v0.1 产品方案

> **从你的工作里，长出你的工作台。**

版本：v0.1
日期：2026-08-17

---

## 一、产品定位

**鹿角蕨（Lujiaojue）是一套运行在超级 Agent 之上的生成式工作台（Generative Workbench）。**

它不替代 ChatGPT、Codex、Claude Code、WorkBuddy 等超级 Agent，也不是一套预先设计好的固定工作台模板。

鹿角蕨从用户真实存在的：

* 文件；
* 文件夹；
* 项目；
* 创作；
* 工作习惯；

开始理解用户正在做什么，并逐渐生成一套适合这个用户自己的工作环境。

核心路径：

```text
真实工作
  ↓
工作空间感知
  ↓
识别工作对象
  ↓
生成工作台
  ↓
按需调用专业 Advisor
  ↓
持续修正和生长
```

核心命题：

> **工作台不是配置出来的，而是从用户真实工作中逐渐长出来的。**

---

# 二、鹿角蕨解决什么问题

今天大多数 AI 工作台有一个共同前提：

> 用户已经知道自己应该怎样管理工作。

但现实往往相反。

普通用户的工作环境通常是：

```text
桌面
├── 新建文件夹
├── 最终版
├── 最终版2
├── 2026活动
├── 老项目
├── 临时
├── 微信下载
└── 各种 Word / PPT / Excel
```

用户可能正在同时：

* 推进几个项目；
* 长期维护一些资源池；
* 写文章；
* 做培训；
* 做研究；
* 处理大量临时材料。

但这些东西并没有被整理成一个明确的“工作系统”。

鹿角蕨不要求用户先整理完，再开始使用 AI。

而是：

> **先理解混乱，再帮助用户逐渐形成秩序。**

---

# 三、产品架构

鹿角蕨不是“大一统 Agent”。

它由三层组成：

```text
超级 Agent
    ↓
鹿角蕨 Core
    ↓
工作空间 + 工作台
    ↓
专业 Advisor
```

具体结构：

```text
鹿角蕨
│
├── Core
│   ├── 工作空间感知
│   ├── 工作对象识别
│   ├── 生命周期管理
│   ├── Advisor 路由
│   └── 工作台生成
│
├── 富丽 Fuli
│   └── 工作与创作复利 Advisor
│
└── 小王 Xiaowang
    └── 项目推进 Advisor
```

未来还可以继续长出新的 Advisor。

但原则不是：

> 不断增加人格。

而是：

> **只有出现长期稳定、独立的问题领域，才增加新的 Advisor。**

---

# 四、Core｜鹿角蕨公共层

鹿角蕨 Core 只处理真正公共的问题。

## 1. Workspace Understanding

理解当前工作空间：

* 有哪些主要目录；
* 最近在使用什么；
* 哪些文件属于同一工作；
* 哪些目录长期活跃；
* 哪些可能是项目；
* 哪些可能是持续资源；
* 哪些可能是创作；
* 哪些暂时无法识别。

第一原则：

> **先建立地图，不急着搬家。**

默认不：

* 自动移动大量文件；
* 批量重命名；
* 强行创建标准目录；
* 把所有文件重新分类。

---

## 2. Work Object

鹿角蕨的基本管理对象不是“文件”，而是：

> **工作对象。**

例如：

```text
开放原子开源实践计划
企业开源培训体系
鹿角蕨
高校教学资源库
产业研究
讲师池
```

这些对象可能对应：

* 一个文件夹；
* 一个 Git 仓库；
* 多个文件夹；
* 一组长期更新的文档；
* 一个远程协作空间。

工作对象不要求结构完全标准化。

---

## 3. Router

鹿角蕨判断当前任务是否需要专业 Advisor。

例如：

```text
帮我找一下这个文件
→ 宿主 Agent 直接完成

这个项目是不是偏航了？
→ 小王

这次工作有什么值得沉淀？
→ 富丽

帮我改一下 PPT
→ 宿主 Agent

这个培训项目最后应该交付什么？
→ 小王

这套课程研发有没有形成长期作品？
→ 富丽
```

原则：

> **能由宿主 Agent 直接完成的，不调用 Advisor。**

---

# 五、Advisor｜专业能力层

Advisor 是鹿角蕨中的专业判断能力。

它们可以独立存在、独立升级、独立测试。

---

## 1. 富丽 Fuli

定位：

> **发现工作中值得复利的东西。**

富丽关注：

* 创作；
* 研究；
* 方法论；
* 工作流；
* 内容资产；
* 认知积累；
* 作品；
* 长期个人资产。

典型问题：

```text
富丽扫描
这次工作有什么值得留下来的？
这个东西值得继续做成作品吗？
最近有什么重复出现的认知？
这个流程有没有可能变成 Skill？
```

富丽并不接管普通工作。

完成判断后立即退出。

---

## 2. 小王 Xiaowang

定位：

> **从项目文件入手，让项目不断向成果闭环收敛。**

小王重点关注：

* 目标；
* 需求；
* 成果；
* 利益相关方；
* 权责；
* 决策；
* 节点；
* 进度；
* 偏航；
* 验收；
* 闭环。

典型问题：

```text
小王扫描
小王整理
这个项目现在卡在哪里？
目标是不是已经发生偏移？
当前真正需要领导确认什么？
哪个文件已经不能代表当前事实？
```

---

# 六、复合型工作

现实工作不是简单的“项目”或者“创作”。

很多工作同时存在两种属性。

例如：

```text
开放原子开源实践计划
```

作为项目，小王关注：

```text
目标
预算
角色
节点
交付物
验收
```

作为长期积累，富丽关注：

```text
是否形成教学模式
是否产生可复用方法
是否形成长期资源
是否可以作品化
是否产生新的认知
```

因此鹿角蕨不问：

> 这个项目属于富丽还是小王？

而问：

> **当前这个问题需要什么判断能力？**

---

# 七、Advisor 生命周期

所有 Advisor 遵循统一生命周期：

```text
默认 inactive

用户任务
 ↓
识别是否需要 Advisor
 ↓
加载最小必要 Advisor
 ↓
执行当前任务
 ↓
任务结束
 ↓
立即退出
```

最高原则：

> **Advisor 是能力，不是 Agent 的永久人格。**

禁止：

```text
加载小王
↓
整个会话都变成小王
```

也禁止：

```text
调用富丽一次
↓
之后所有问题都用复利创作框架解释
```

统一采用：

> **最小对象、最小上下文、最短生命周期。**

---

# 八、Advisor 独立演化机制

这是鹿角蕨架构中的核心原则之一。

富丽、小王虽然进入同一个仓库，但仍然是：

> **可以独立升级的产品模块。**

例如：

```text
鹿角蕨     v0.1
富丽       v0.5
小王       v0.4
```

未来可以变成：

```text
鹿角蕨     v0.3
富丽       v0.9
小王       v0.6
```

三者版本不绑定。

---

## Advisor First 原则

专业能力优先留在所属 Advisor 内。

例如：

```text
项目偏航检测
→ 小王

作品发布跟踪
→ 富丽

复利创作规范
→ 富丽

项目成果验收
→ 小王
```

只有当一个能力已经明确属于多个 Advisor 的稳定公共需求，才进入 Core。

例如：

```text
生命周期管理
工作空间读取
Advisor 调度
用户公共偏好
```

原则：

> **不要因为两个 Advisor 都“可能需要”，就提前抽成公共能力。**

---

# 九、单个 Advisor 如何升级

用户未来可以直接说：

```text
升级小王
```

或者：

```text
升级富丽
```

系统自动限定修改范围。

例如升级小王：

```text
允许：
skills/xiaowang/
evals/xiaowang/

默认不允许：
skills/fuli/
core/
```

只有确定存在公共能力变化时，才允许修改 Core。

---

## 版本规则

每个 Advisor 自己维护：

```text
SKILL.md
VERSION
CHANGELOG.md
```

例如：

```text
skills/xiaowang/VERSION

0.4.0
↓
0.5.0
```

Git Commit：

```text
feat(xiaowang): add project drift detection
```

Tag：

```text
xiaowang-v0.5.0
```

富丽同理：

```text
feat(fuli): add publication tracking
```

Tag：

```text
fuli-v0.6.0
```

# 十、鹿角蕨初始化

v0.1 最重要的入口：

> **鹿角蕨初始化**

用户指定一个工作目录。

鹿角蕨进行轻量扫描：

```text
文件夹
+
文件类型
+
更新时间
+
Git 仓库
+
关键文件
+
近期活动
```

然后识别候选工作对象。

例如：

```text
我的工作

正在进行
├── 开源实践计划
├── 鹿角蕨
└── 企业开源培训

持续积累
├── 高校教学资源
├── 讲师池
└── 产业研究

近期变化
├── 3 个工作对象本周更新
└── 1 个长期项目近 30 天无变化
```

用户可以：

```text
确认
修改
忽略
合并
```

鹿角蕨逐步修正理解。

---

# 十一、生成式工作台

初始化后，鹿角蕨生成第一版工作台。

v0.1 不追求复杂。

只回答三个问题：

> **我正在做什么？**

> **什么发生了变化？**

> **什么值得我关注？**

示意：

```text
┌─────────────────────────────┐
│ 鹿角蕨                      │
│ 从你的工作里长出工作台      │
├─────────────────────────────┤
│ 最近工作                    │
│                             │
│ 开源实践计划       ● Active │
│ 鹿角蕨             ● Active │
│ 企业培训           ○ Recent │
├─────────────────────────────┤
│ 最近变化                    │
│                             │
│ 开源实践计划 今日更新        │
│ 鹿角蕨       新增 4 个文件   │
├─────────────────────────────┤
│ 值得注意                    │
│                             │
│ 1 个项目出现偏航信号         │
│ 2 个工作出现复利资产信号     │
└─────────────────────────────┘
```

---

# 十二、工作台不是任务管理器

鹿角蕨 v0.1 不尝试替代：

* Notion；
* 飞书；
* 企业微信；
* Trello；
* Jira；
* GitHub Projects。

它的核心价值不是：

> 管理更多任务。

而是：

> **理解用户正在做什么。**

工作台只是这种理解的可视化结果。

---

# 十三、用户状态目录

用户项目统一使用：

```text
.lujiaojue/
```

不再长期建立：

```text
.fuli/
.xiaowang/
```

第一版尽量只保留：

```text

```

其中保存：

```text

识别状态
最近变化
少量长期偏好

```

不保存完整用户历史。

不制造大型知识库。

# 十五、根 SKILL.md 的职责

鹿角蕨根目录：

```text
SKILL.md
```

不负责实现全部能力。

只负责：

### 1. 判断鹿角蕨是否应该介入

例如：

```text
鹿角蕨初始化
打开工作台
看看最近工作
```

### 2. 管理工作空间上下文

### 3. 判断是否调用 Advisor

```text
项目判断 → 小王
复利判断 → 富丽
普通任务 → 宿主 Agent
```

### 4. 控制 Advisor 生命周期

### 5. 防止专业能力相互污染

因此：

> **根 SKILL 是 Router，不是 Super Advisor。**

# 十九、Git 开发方式

长期只维护：

```text

```

作为稳定主干。

升级 Advisor 时使用短期分支：

```text
advisor/xiaowang-v0.5

```

```text

```

完成后合并回：

```text

```

然后删除分支。

不为富丽、小王维护永久分支。

# 二十、版本体系

鹿角蕨采用：

```text
平台版本
+
Advisor 独立版本
```

例如：

```text
鹿角蕨 0.1.0
├── 富丽 0.5.0
└── 小王 0.4.0
```

只有涉及：

* Core；
* 工作台；
* 初始化；
* Router；
* 公共状态；
* 安装升级机制；

等整体能力变化时，才升级鹿角蕨版本。

单纯：

```text
小王 0.4 → 0.5
```

不要求鹿角蕨同步升级大版本。

# 二十一、v0.1 最小范围

第一版只完成四件事：

```text
工作空间感知
+
工作对象识别
+
生成工作台
+

```

明确不做：

* 独立桌面 App；
* 新聊天 UI；
* 通用任务管理器；
* 企业知识库；

# 二十三、核心产品原则

### 1. Native First

宿主 Agent 已经能完成的事情，不重复建设。

### 2. Minimum Scope

只读取当前任务真正需要的最小上下文。

### 3. Advisor First

专业能力优先在 Advisor 内独立成长，不轻易污染 Core。

### 4. Grow, Don't Configure

不是要求用户先配置系统，而是从真实工作中逐渐生成系统。

### 5. Organize by Value

整理的目标不是文件整齐，而是：

> 降低理解、决策、协作和创作成本。

### 6. Progressive Personalization

先给可用默认值，再通过真实使用逐渐了解用户。

### 7. No Unnecessary Entity

没有明确价值，不增加：

* 文件；
* 目录；
* 状态；
* Advisor；
* 模板；
* 数据字段；
* 系统层。

---

# 二十四、鹿角蕨真正的长期方向

鹿角蕨不是：

> 富丽 + 小王。

也不是：

> AI 文件整理工具。

更不是：

> 一个漂亮的 Dashboard。

它真正要建立的是：

```text
Workspace Understanding
        ↓
Work Model
        ↓
Generative Workbench
        ↓
Professional Advisors
        ↓
Long-term Adaptation
```

也就是：

> **让 AI 不只是完成一次任务，而是逐渐理解一个人如何工作，并从真实工作中长出适合他的工作系统。**

这才是“鹿角蕨”这个产品长期存在的核心价值。
