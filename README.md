# 鹿角蕨 v0.1

> **从你的工作里，长出你的工作台。**

版本：v0.1
日期：2026-08-17

---

## 一、这是什么

**鹿角蕨（Lujiaojue）是一套运行在超级 Agent 之上的生成式工作台（Generative Workbench）。**

你已经在用 ChatGPT、Codex、Claude Code、WorkBuddy 这样的超级 Agent 了。鹿角蕨不会替代它们，也不是给你一套提前设计好、让你照搬的固定模板。

它从你真实存在的东西出发：

* 文件；
* 文件夹；
* 项目；
* 创作；
* 工作习惯；

一点一点读懂你正在做什么，然后长出一套只属于你的工作环境。

它会这样一步步来：

```text
你的真实工作
  ↓
看懂你的工作空间
  ↓
认出你在做什么
  ↓
长出你的工作台
  ↓
按需叫来专业顾问
  ↓
持续修正、继续生长
```

一句话：

> **工作台不是配置出来的，而是从你的真实工作里慢慢长出来的。**

---

# 二、它帮你解决什么

大多数 AI 工作台都有一个默认前提：

> 你早就知道自己该怎么管理这些工作了。

但现实往往不是这样。

你的工作环境，很可能长这样：

```text
桌面
├── 新建文件夹
├── 最终版
├── 最终版2
├── 2026活动
├── 老项目
├── 临时
├── 微信下载
└── 各种 Word / PPT / Excel
```

你可能同时在：

* 推进几个项目；
* 长期维护一些资源池；
* 写文章；
* 做培训；
* 做研究；
* 处理大量临时材料。

但这些都还没被整理成一个清晰的「工作系统」。

鹿角蕨不要求你先把一切整理好，再来用 AI。

它做的是：

> **先接受你的混乱，再陪你把秩序慢慢长出来。**

---

# 三、它是怎么运转的

鹿角蕨不是一个「包办一切的 Agent」。

它分三层：

```text
超级 Agent
    ↓
鹿角蕨 Core
    ↓
工作空间 + 工作台
    ↓
专业 Advisor
```

拆开看：

```text
鹿角蕨
│
├── Core
│   ├── 看懂工作空间
│   ├── 认出工作对象
│   ├── 管理生命周期
│   ├── 路由到顾问
│   └── 生成工作台
│
├── 富丽 Fuli
│   └── 工作与创作复利顾问
│
└── 小王 Xiaowang
    └── 项目推进顾问
```

以后还可以长出新的顾问。

但原则不是「人越多越好」：

> 不断增加人格。

而是：

> **只有当某个问题领域长期、稳定、独立存在时，才新增一位顾问。**

# 四、鹿角蕨的基础能力

鹿角蕨 Core 只处理真正公共的事。

## 1. 看懂你的工作空间

它先弄明白你眼前有什么：

* 有哪些主要目录；
* 你最近在用什么；
* 哪些文件属于同一件事；
* 哪些目录长期活跃；
* 哪些可能是项目；
* 哪些可能是长期资源；
* 哪些可能是创作；
* 哪些暂时还认不出。

第一步的原则：

> **先画地图，不急着搬家。**

它默认不会：

* 自动移动大量文件；
* 批量重命名；
* 强行建立标准目录；
* 把所有文件重新分类。

---

## 2. 认出你的工作对象

鹿角蕨管理的基本单位不是「文件」，而是：

> **工作对象。**

比如：

```text
开放原子开源实践计划
企业开源培训体系
鹿角蕨
高校教学资源库
产业研究
讲师池
```

一个工作对象，可能对应：

* 一个文件夹；
* 一个 Git 仓库；
* 多个文件夹；
* 一组长期更新的文档；
* 一个远程协作空间。

工作对象不要求结构完全统一。

---

## 3. 该不该叫顾问，它来判断

鹿角蕨会判断你当前这件事，需不需要专业顾问上场。

比如：

```text
帮我找一下这个文件
→ 宿主 Agent 直接办

这个项目是不是偏航了？
→ 小王

这次工作有什么值得沉淀？
→ 富丽

帮我改一下 PPT
→ 宿主 Agent

这个培训项目最后应该交付什么？
→ 小王

这套课程研发有没有形成长期作品？
→ 富丽
```

原则：

> **宿主 Agent 能直接办的，就不叫顾问。**

# 五、你的两位专业顾问

Advisor 是鹿角蕨里的专业判断能力。

它们各自独立存在、独立升级、独立测试。

---

## 1. 富丽 Fuli

富丽帮你：

> **发现工作中值得复利的东西。**

她关注：

* 创作；
* 研究；
* 方法论；
* 工作流；
* 内容资产；
* 认知积累；
* 作品；
* 长期个人资产。

你可以这样问她：

```text
富丽扫描
这次工作有什么值得留下来的？
这个东西值得继续做成作品吗？
最近有什么重复出现的认知？
这个流程有没有可能变成 Skill？
```

富丽不会接管你的日常工作。

她判断完，就退场。

---

## 2. 小王 Xiaowang

小王帮你：

> **从项目文件入手，让项目一步步收敛到成果闭环。**

小王盯的是：

* 目标；
* 需求；
* 成果；
* 利益相关方；
* 权责；
* 决策；
* 节点；
* 进度；
* 偏航；
* 验收；
* 闭环。

你可以这样问他：

```text
小王扫描
小王整理
这个项目现在卡在哪里？
目标是不是已经发生偏移？
当前真正需要领导确认什么？
哪个文件已经不能代表当前事实？
```

# 六、一件工作，两种属性

真实的工作，很少是纯粹的「项目」或「创作」。

很多事同时兼有两者。

比如：

```text
开放原子开源实践计划
```

作为项目，小王会盯：

```text
目标
预算
角色
节点
交付物
验收
```

作为长期积累，富丽会盯：

```text
是否形成教学模式
是否产生可复用方法
是否形成长期资源
是否可以作品化
是否产生新的认知
```

所以鹿角蕨不会问：

> 这件事属于富丽还是小王？

它只会问：

> **你眼下这个问题，需要哪一种判断力？**

---

# 7、顾问随叫随到，用完即走

所有顾问遵循同一条生命线：

```text
默认不打扰你

你发起任务
 ↓
判断要不要顾问
 ↓
只加载最小的那位顾问
 ↓
办完当前这件事
 ↓
任务结束
 ↓
立即退场
```

最高原则：

> **顾问是一种能力，不是 Agent 永远戴着的人格面具。**

它禁止这种事：

```text
叫来小王
↓
整个会话都变成小王
```

也禁止：

```text
叫富丽一次
↓
之后所有问题都用「复利创作」框架去套
```

统一采用：

> **最小对象、最小上下文、最短生命周期。**

---

# 八、每位顾问独立成长

这是鹿角蕨架构的核心之一。

富丽、小王虽然进了同一个仓库，但仍然是：

> **可以各自独立升级的产品模块。**

比如：

```text
鹿角蕨     v0.1
富丽       v0.5
小王       v0.4
```

以后可以变成：

```text
鹿角蕨     v0.3
富丽       v0.9
小王       v0.6
```

三者版本互不绑定。

---

## 顾问优先原则

专业能力，优先留在它所属的顾问里。

比如：

```text
项目偏航检测
→ 小王

作品发布跟踪
→ 富丽

复利创作规范
→ 富丽

项目成果验收
→ 小王
```

只有当一项能力已经明确是多个顾问都稳定需要的公共需求时，才进 Core。

比如：

```text
生命周期管理
工作空间读取
顾问调度
你的公共偏好
```

原则：

> **别因为两位顾问「都可能会用到」，就提前抽成公共能力。**

---

# 九、怎么单独升级一位顾问

你以后可以直接说：

```text
升级小王
```

或者：

```text
升级富丽
```

系统会自动限定修改范围。

比如升级小王：

```text
允许改：
skills/xiaowang/
evals/xiaowang/

默认不许动：
skills/fuli/
core/
```

只有确认涉及公共能力变化时，才允许改 Core。

---

## 版本规则

每位顾问自己维护：

```text
SKILL.md
VERSION
CHANGELOG.md
```

比如：

```text
skills/xiaowang/VERSION

0.4.0
↓
0.5.0
```

Git 提交：

```text
feat(xiaowang): add project drift detection
```

打标签：

```text
xiaowang-v0.5.0
```

富丽同理：

```text
feat(fuli): add publication tracking
```

标签：

```text
fuli-v0.6.0
```

```text
+
```


# 二十三、核心原则

### 1. Native First

宿主 Agent 已经能办的事，不重复建设。

### 2. Minimum Scope

只读取当前任务真正需要的最小上下文。

### 3. Advisor First

专业能力优先在顾问内独立成长，不轻易污染 Core。

### 4. Grow, Don't Configure

不要求你先配置系统，而是从真实工作里慢慢长出系统。

### 5. Organize by Value

整理的目标不是文件整齐，而是：

> 降低理解、决策、协作和创作的成本。

### 6. Progressive Personalization

先给你可用的默认值，再通过真实使用逐渐懂你。

### 7. No Unnecessary Entity

没有明确价值，就不增加：

* 文件；
* 目录；
* 状态；
* 顾问；
* 模板；
* 数据字段；
* 系统层。

---

# 二十四、它最终要去哪

鹿角蕨不是：

> 富丽 + 小王。

也不是：

> AI 文件整理工具。

更不是：

> 一个漂亮的 Dashboard。

它真正要建立的，是这样一条路：

```text
Workspace Understanding
        ↓
Work Model
        ↓
Generative Workbench
        ↓
Professional Advisors
        ↓
Long-term Adaptation
```

也就是：

> **让 AI 不只是帮你完成一次任务，而是逐渐理解你这个人是怎么工作的，并从你的真实工作里，长出属于你的工作系统。**

这才是「鹿角蕨」这个产品长期存在的核心价值。
