# 鹿角蕨 Lujiaojue

> **从你的工作里，长出你的工作台。**

鹿角蕨运行在你已经使用的超级 Agent 中。

它不会替代 WorkBuddy、Codex、Claude Code，而是让这些 Agent 从你的真实文件和项目开始理解你的工作，并在需要时调用专业能力、生成适合你的工作台。

## 使用前提

先准备一个能够读取和操作本地工作文件的超级 Agent，例如：

- WorkBuddy
- Codex
- Claude Code
- 其他支持 Skills / Plugins 的 Agent

然后把鹿角蕨安装到这个 Agent 中。

> **推荐全局安装。**  
> 这样你打开不同工作目录时，都可以继续使用鹿角蕨。

---

## 安装

### Claude Code

本仓库可直接作为 Claude Code Plugin 使用。

测试本地仓库：

```bash
claude --plugin-dir ./lujiaojue
```

从 GitHub 仓库安装（仓库发布后）：

```text
/plugin marketplace add ydj9931/lujiaojue
/plugin install lujiaojue@lujiaojue
```

### Codex

鹿角蕨的能力按照 Agent Skills 结构组织。

最简单的方式是把仓库地址交给 Codex，让它使用自己的 Skill 安装能力安装：

```text
请把 https://github.com/ydj9931/lujiaojue 中的鹿角蕨、富丽、小王 Skills
安装为全局可复用能力。优先使用你原生的 Skill / Plugin 安装机制。
```

如果你的 Codex 工作区已经提供 Plugin / Skills UI，也可以从相应入口安装。

### WorkBuddy

在 WorkBuddy 中打开技能（Skills）入口，通过 Skill Marketplace、导入能力或自然语言创建/安装功能，把本仓库中的鹿角蕨能力安装为全局 Skill。

你也可以直接告诉 WorkBuddy：

```text
请从 https://github.com/ydj9931/lujiaojue 安装鹿角蕨。
把它作为全局可复用 Skill 使用，并同时安装富丽和小王两个 Advisor。
```

不同 Agent 的安装界面可能不同，但用户不需要手工运行鹿角蕨的 Python 脚本。

## 第一次使用

安装后，打开你平时真正工作的文件夹。

然后告诉 Agent：

```text
鹿角蕨初始化
```

鹿角蕨会：

```text
扫描当前工作空间
→ 识别候选工作对象
→ 建立 .lujiaojue/ 状态
→ 生成第一版工作台
→ 自动打开或展示工作台
```

第一次初始化遵循：

> **先理解，不折腾。**

默认不会为了“标准化”而批量移动、改名或重构你的文件。

## 平时怎么用

初始化之后，你可以继续像平时一样和 Agent 工作。

例如：

```text
帮我看看这个项目现在最关键的问题。
```

```text
这份方案还有什么没有想清楚？
```

```text
我最近做的这些培训，有什么已经值得长期沉淀？
```

鹿角蕨会判断当前问题是否需要专业 Advisor。

目前内置：

### 小王

负责项目推进与成果闭环。

可以直接说：

```text
小王扫描
小王整理
这个项目是不是偏航了？
```

### 富丽

负责发现工作中值得长期复利的东西。

可以直接说：

```text
富丽扫描
这次工作有什么值得留下来？
这个方法值得长期沉淀吗？
```

Advisor 完成当前任务后自动退出，不会持续接管你的 Agent。

## 打开工作台

告诉 Agent：

```text
鹿角蕨工作台
```

工作台优先回答三个问题：

> **我最近在做什么？**  
> **什么发生了变化？**  
> **现在什么值得关注？**

工作台由鹿角蕨自动生成。

HTML 只是当前版本的显示方式，不是需要用户单独安装或维护的产品。

## 怎么用好

### 直接放进真实工作

不要为了使用鹿角蕨先搭一套新文件系统。

把它放进你已经在工作的目录，让它从真实状态开始理解你。

### 发现识别错误就直接纠正

例如：

```text
这个不是项目，是长期维护的讲师池。
```

```text
这两个目录其实属于同一个工作。
```

```text
这个项目已经结束了。
```

鹿角蕨应该逐渐修正，而不是要求你第一次配置就全部正确。

### 少做无意义的管理动作

你随时可以说：

```text
先记着，不处理。
```

好的鹿角蕨应该减少管理负担，而不是制造更多文件、模板、字段和任务。

---

## 让鹿角蕨适合你

直接用自然语言告诉它你的长期偏好。

例如：

```text
项目文件尽量少，能一个文件解决就不要拆三个。
```

```text
默认只告诉我最重要的三件事。
```

```text
我喜欢先看结论，再看证据。
```

```text
不要为了目录整齐移动我的历史文件。
```

原则是：

> **先使用，再适配。**

不需要第一次使用就填写复杂配置。
