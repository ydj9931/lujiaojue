# 项目文件原则

项目文件不是为了保存过程，而是为了把事情做成。

完整指南见 `project-file-guide.md`。

## 最小健康标准

项目文件只要能够快速回答四问，就基本健康：

1. 最终成果是什么？
2. 当前事实在哪里？
3. 当前最重要的待决策是什么？
4. 最终成果在哪里？

## 文件角色

只理解五种角色，不机械建立五个目录：

- 项目入口；
- 当前推进；
- 决策；
- 成果；
- 历史。

## 单一事实源

一个事实，只维护一个当前来源。

已有在线表格、Issues、协作文档承担事实源时，不创建平行文件。

## 历史退出

历史可以多，但当前必须少。

旧版本、旧方案、过期汇报退出当前工作区即可，不以删除为目标。

## 新增文件前

先问：

> 如果没有这份文件，会不会明显影响理解、决策、协作、推进或交付？

不会，就不建。
